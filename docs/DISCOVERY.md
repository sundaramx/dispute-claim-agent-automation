# Discovery — dispute-claim-agent-automation

**Idea:** Agentic AI automation for card dispute & claims operations: intake → triage → investigation → resolution/implementation (decision, provisional credit, chargeback filing, customer comms) → monitoring, with human-in-the-loop approvals, Reg E/Reg Z deadlines and a tamper-evident audit trail.

**Standards:** quality floor only (no company pack)

## Spec summary

- Product: agentic automation for issuer-side card dispute and claims operations at a mid-size US card issuer. Pipeline is intake → triage → investigation → resolution/implementation (decision, provisional credit, chargeback filing, customer comms) → monitoring. It is a production-grade MVP running against simulated integrations.
- Success metrics: 100% Reg E/Reg Z deadline compliance (zero misses), at least 50% reduction in handling time per case, and every decision reproducible from the audit trail (inputs, policy version, model/prompt version, outputs).
- Scope: debit (Reg E) and credit (Reg Z) disputes on Visa and Mastercard through an extensible network adapter. Covers all five categories: fraud/unauthorized, non-receipt, not-as-described, duplicate, credit-not-processed. Runs through first chargeback and representment response.
- Out of scope: acquirer side, ACH/P2P, Amex/Discover, and pre-arbitration/arbitration. Pre-arb and arbitration cases are flagged to a human and routed to a manual queue.
- Regulatory clocks: reuse the Reg E/Z clock engine and business-day calendar. Reg E: 10 business days to investigate or grant provisional credit, extendable to 45 or 90 days; written notices at each step. Reg Z: written acknowledgment within 30 days, resolution within 2 billing cycles and no more than 90 days. Network filing windows by reason code (inferred).
- Default HITL mode: the agent autonomously handles intake, triage, evidence gathering, deadline computation, and drafting of decisions and letters. A human approves every money movement (provisional credit, final credit/debit, write-off), every chargeback filing, and every outbound customer communication. Amounts over $500 or low-confidence cases need Supervisor sign-off.
- Low-risk auto-approve mode: an Admin can toggle it at runtime; it is OFF by default and every toggle is audit-logged. When ON, high-confidence cases under a configurable dollar threshold get provisional credit and chargeback filing executed automatically. Every auto-action is logged, and a configurable sample (default 10%, inferred) goes to Supervisor QA. Customer comms still require approval (inferred, conservative).
- Roles and RBAC: Analyst, Supervisor, Compliance Auditor (read-only), and Admin. Four-eyes is enforced: approver must differ from preparer. Local auth uses OIDC-compatible JWT with seeded users, SSO-ready (inferred).
- Intake channels: REST API, an analyst console manual-entry form, and a mocked customer portal/IVR feed. Free text is LLM-extracted into a structured claim and then validated (inferred).
- Decisioning: policy-as-code (reused) produces deterministic rule outcomes, and the LLM supplies evidence summarization, classification, reason-code mapping, and letter drafting. Confidence is a calibrated composite of rule coverage, evidence completeness, and model self-score (inferred). The LLM never makes money decisions outside the policy guardrails.
- Stack: Python 3.12 + FastAPI, PostgreSQL, a Postgres-backed durable workflow/state machine (idempotent steps, retries, timers for deadlines), and a React/TypeScript analyst console with case queue, case detail, approvals inbox, SLA dashboard, admin config, and audit viewer.
- LLM gateway: providers are Ollama (local default), AWS Bedrock (AsyncAnthropicBedrock with application-inference-profile ARN and guardrail headers), Google Gemini, and any OpenAI-compatible API. Provider and model are configurable per environment and per agent task, with failover. Cost, latency, and token usage are tracked per call.
- Data protection: PANs are tokenized and never sent to an LLM; PII is redacted in prompts. US data residency, PCI-DSS-aware design, and encryption at rest and in transit. Secrets come from environment variables locally and AWS Secrets Manager in Terraform (inferred).
- Integrations: all mocked behind clean adapter interfaces. These cover the core ledger, card processor, Visa VROL, Mastercom, CRM, and notifications (email/letter/SMS). Includes a synthetic dispute data generator and seeded scenarios for all categories and edge cases (inferred).
- Audit: an append-only, hash-chained event log in Postgres (reused ledger), with a verification endpoint/CLI and optional S3 Object Lock (WORM) anchoring behind a config flag. The 7-year retention policy is documented.
- Operations: runs locally via docker compose. Terraform for AWS ECS (dev/staging/prod) is written but not applied. OpenTelemetry metrics and traces, with alerts on SLA-at-risk cases (T-2 business days), agent errors, and LLM cost/latency spikes.
- Scale: designed for about 5k disputes/month and scalable 10x via horizontal workers on the Postgres queue. Target 99.5% availability for the MVP and console p95 under 500 ms excluding LLM calls (inferred).
- Quality: pytest unit/integration tests, deadline-engine property tests, a golden-case eval harness for agent outputs, Playwright smoke tests for the console, and CI lint/type checks with ruff, mypy, and tsc (inferred). Tradeoffs are recorded in TRADEOFFS.md.
