# PLAN — dispute-claim-agent-automation

> Status: **Draft v1 for design review**. Owner: Orchestrator. Date: 2026-10-28.
> Inputs: `PRD.md` (FR-1..FR-35, NFR-1..NFR-14), `ARCHITECTURE.md` (components C1–C25, layout §9), `TRADEOFFS.md` (TD-1..TD-48), `docs/DISCOVERY.md`.
> CR-1 (2026-10-29) adds FR-36, FR-37, components C26–C27, TD-53..TD-57 and milestone M11 (T102–T111).
> Standards: **quality floor only** (no company pack resolved). No implementation code is written until the human gives an explicit green light at the design review gate.
> This file is the source of truth for the build. If the build deviates, this file is updated first. Task IDs are stable: they are never renumbered, and new tasks are appended at the end.

Conventions used by every task:
- Python commands run from the repo root against the project virtualenv `.venv/` (created by T2 with `uv`, Python 3.12). Tests live under `backend/tests/`.
- Console commands run inside `console/` with the project-local `node_modules` (`npx` resolves locally).
- Terraform, tflint and gitleaks are downloaded by T7 into `./.tools/bin/` (pinned and checksum-verified). Nothing is installed globally.
- Integration tests get a disposable PostgreSQL 16 from `docker-compose.test.yml`, started automatically by the session fixture from T4.
- CI and every check use the deterministic `mock` LLM provider and mocked adapters. No network calls, no paid LLM calls (NFR-10 AC 6).
- Roles: **Implementer** builds. **Validator** certifies, and is never the Implementer of the same task. **Security** audits. **Documentation** owns `docs/`, `README.md` and `prototype/`. **Architecture** owns `ARCHITECTURE.md` and `TRADEOFFS.md`.

Verify: `make ci`

## Definition of Done

The build is done only when **all** of the following hold:

1. **Build passes.** `make ci` (the Verify command) exits 0 on a clean checkout: images build, migrations install fresh and upgrade, and every lint, type, test, eval, e2e and IaC check is green.
2. **Tests are green.** Unit, property, integration, fault, security, golden eval and Playwright suites all pass. Coverage is ≥ 80% on `dca.regclock`, `dca.policy`, `dca.approvals`, `dca.audit` and `dca.protect` (NFR-10 AC 1).
3. **Every acceptance criterion is met.** Each FR-1..FR-35 and NFR-1..NFR-14 acceptance criterion is satisfied with evidence. Success metrics SM-1..SM-5 are shown on the seeded corpus: zero missed deadlines, the handling-time report is produced, 100% replay match, 100% tamper detection, zero PANs in any LLM payload or log.
4. **Validator certification is recorded** in `docs/CERTIFICATION.md` by a Validator who did not implement the work (T101), including the Security review (T99). Every task in this plan is checked off only after its certification entry exists.
5. **The app runs.** `make up && make seed` brings up the full stack with healthy services within 2 minutes, and the console is reachable at `http://localhost:8080` with the seeded users. `make up LLM=mock` works on machines without Ollama.
6. **Traceability holds.** Every FR/NFR maps to ≥ 1 checked task, and every task maps to ≥ 1 FR/NFR. `TRADEOFFS.md` has an entry for every consequential build-time decision. Inferred defaults and unconfirmed seed data (OQ-1..OQ-8, AS-1, AS-2) are flagged in the certification.
7. **Hygiene.** No secrets in the repo (gitleaks clean), `.env` never committed, commits made with specific `git add` paths only, and Terraform validated but never applied.

## Verification strategy & standards

### Test levels

| Level | Tool | Location | Scope |
|---|---|---|---|
| Unit | pytest | `backend/tests/unit/` | Pure modules (regclock, policy, confidence, protect, config validation, auth, gateway with mock provider), in-process adapter fakes |
| Property | Hypothesis | `backend/tests/property/` | Business-day calendar, Reg E/Z clocks, policy determinism (FR-4 AC 8, NFR-10 AC 2, NFR-11) |
| Integration | pytest + disposable Postgres 16 (`docker-compose.test.yml`) | `backend/tests/integration/` | DB migrations, grants and triggers, audit chain, workflow queue, API with RBAC matrix, agents, executor, mocks and vault services, scheduler |
| Fault injection | pytest + subprocess SIGKILL + mock fault headers | `backend/tests/fault/` | Exactly-once effects, crash recovery, timers surviving restarts (NFR-4, FR-20 AC 3) |
| Security | pytest | `backend/tests/security/` | Prompt injection, PAN egress scan (SM-5), console headers, agent capability scoping, DB grants |
| Agent eval | vendored agent-eval harness, `dca eval --suite golden` | `eval/` | Extraction accuracy, classification ≥ 95%, reason-code agreement ≥ 95%, citation validity, ECE ≤ 0.10, injection resistance 100% |
| Console component | Vitest + Testing Library (TD-49) | `console/src/**/*.test.tsx` | Page behaviour against stubbed API responses |
| End-to-end | Playwright + axe-core | `console/e2e/` | Role logins, approve flow in ≤ 3 clicks, four-eyes denial, auto-approve toggle, audit verify, WCAG 2.1 AA |
| Performance | `dca loadtest` | `backend/tests/load/` | NFR-1 p95 < 500 ms, NFR-2 10× backlog, NFR-7 1M-event verify < 60 s |
| Determinism | pytest | integration | Same seed ⇒ byte-identical corpus and identical audit head hash; 100% replay match (SM-3) |

Each task's check proves that task alone. Whole-suite gates (coverage floors, full eval, e2e, IaC) run in `make ci`.

### Lint, format and types

- Python: `ruff check` and `ruff format --check` (bandit `S` rules on), `mypy` strict on core packages, `lint-imports` boundary contracts (agents never import mutating adapters or provider SDKs; only `dca.llm.providers` imports `anthropic`, `openai`, `google.genai`; `dca_vault` and `dca_mocks` never import `dca`).
- TypeScript: `tsc --noEmit` with `strict: true`, ESLint (no `dangerouslySetInnerHTML`), and an OpenAPI client drift check.
- Zero errors required (NFR-10 AC 5).

### Security checks

- **Secrets:** gitleaks over the tree and history (zero findings). `.env` gitignored. Secrets are loaded as `SecretStr` and never logged or exposed in `/system/info`.
- **Dependencies:** `uv.lock` and `package-lock.json` pinned. pip-audit and npm audit with zero unresolved critical/high findings. Images pinned by digest, running as non-root with a read-only root filesystem.
- **IaC:** terraform fmt/validate, tflint and checkov with zero high findings, US regions only. Run offline and never applied.
- **Application:** RBAC matrix test (every role × every route), three-layer four-eyes (service, DB trigger, executor re-check), audit immutability grants and triggers, tamper detection, PAN egress fail-closed, log redaction, SSRF allow-list, sandboxed templates, CSP without inline scripts, RS256-pinned JWT, and dev issuer refused outside `local`.
- **LLM rules:** Bedrock only via `anthropic.AsyncAnthropicBedrock` with a full application-inference-profile ARN, mandatory guardrail headers, and credentials from the configured auth refresh command with TTL refresh and auth-error retry. No hard-coded account, profile, role or guardrail IDs.
- **Reviews:** Security records an OWASP Top-10 and agentic review in `docs/CERTIFICATION.md` (T99). An independent Validator certifies every task before it is checked off (separation of duties).

### SDLC standards

- One task, one focused commit: `git add <specific files>` only, never `-A` or `.`. The commit message references the task ID and requirement IDs (e.g. `T13 FR-4: Reg E clock engine`).
- Build loop per task: implement → run the task check → self-correct → independent Validator certification → check off in this file → append any decision to `TRADEOFFS.md` → log in `docs/CERTIFICATION.md` → commit.
- Stop-and-Report applies to: destructive actions outside the project, global installs, real data or credentials, any remote push or deploy, scope changes, or a task failing 3 consecutive fix attempts.
- New ideas are logged as open questions in `PRD.md` and not built (no gold-plating).
